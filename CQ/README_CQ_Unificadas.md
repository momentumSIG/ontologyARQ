## Section 5b: Ontologies Generated by Pattern — DeepSeek-v4

Ontologies generated from the **DeepSeek unified CQs** (50 CQs, 8 blocks) under three patterns using a **block-aware generation** approach. Unlike the keyword-matching approach used for Kimi, these ontologies use the full vocabulary from DeepSeek's own ontological analysis (30+ classes from `docs/objetoArqueologico/analisis_ontologico_deepseek.md`), with block-specific class inventories and CRM-aligned properties.

```

├── pattern_1_event_driven/            ← Event-centric ontology
│   ├── memoryless/temp_0_{3,5,7}/     ← 150 .ttl (block-aware)
│   ├── ontogenia/temp_0_{3,5,7}/      ← 150 steps + 3 cumulative.ttl
│   └── README.md
├── pattern_2_state_transition/          ← State-centric ontology
│   ├── memoryless/temp_0_{3,5,7}/
│   ├── ontogenia/temp_0_{3,5,7}/
│   └── README.md
└── pattern_4_assignment_intrinsic/     ← Reification-centric ontology
    ├── memoryless/temp_0_{3,5,7}/
    ├── ontogenia/temp_0_{3,5,7}/
    └── README.md
```

**Total generated:** 909 .ttl files

**Key improvements over Kimi (script-based) approach:**

| Aspecto | Kimi (script) | DeepSeek (block-aware) |
|---------|--------------|----------------------|
| **Vocabulario** | Genérico, keyword matching | 30+ clases del análisis ontológico de DeepSeek |
| **Estructura** | Una clase por keyword | Fragmentos ontológicos completos por bloque temático |
| **Alineación CRM** | Básica | Cada clase documenta superclase CRM exacta |
| **Ontogenia** | Acumula properties sueltas | Acumula vocabulario completo de cada bloque encontrado |

| **Equivalencia CRM** | No | `HumanMadeObject owl:equivalentClass crm:E22_Human-Made_Object` |

| Dimension | Pattern 1: Event-Driven | Pattern 2: State-Transition | Pattern 4: Assignment-Intrinsic |
|-----------|----------------------|---------------------------|------------------------------|
| **Primary anchor** | Events (E5_Event) | Condition states (E3_Condition_State) | Assignments (E17_Type_Assignment) |

## Notes

- **Spatial/temporal/stratigraphy blocks** for all three models are taken directly from the original v1 generation, as no v2 sets were produced for these blocks.
- Each unified object file includes a header noting which CQs originated from v2 (primary thematic blocks) and which were integrated from v1.
- Block terminology is preserved **as originally generated by each LLM** and is not normalized across models.
- The three unified sets are fully independent: each LLM generated its v2 CQs from scratch without reference to the other models' outputs.
- **Temperature as experimental variable:** 0.3 (conservative), 0.5 (balanced), 0.7 (creative). Restrictions and disjointness axioms are deliberately added only at 0.7 to test the effect of "creative" ontology generation on quality metrics.
- **Why only 0.7 has restrictions:** This is a deliberate experimental design choice. Temperature simulates LLM creativity. At 0.3, the LLM is instructed to be conservative (flat hierarchies, no restrictions). At 0.7, it is instructed to be creative (deep hierarchies, reification, disjointness). This allows comparison of how "creative freedom" affects ontology quality across metrics: semantic consistency, ontology drift, redundancy generation, CIDOC CRM alignment, determinism, ontology stability, hallucinated entities, and CQ coverage.
